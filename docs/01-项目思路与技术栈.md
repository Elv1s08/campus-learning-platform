## 一、项目定位

本项目的本质是**基于 RAG（检索增强生成）的校园学习辅导系统**，而不是训练一个校园大模型。这一边界在答辩时必须讲清楚。

系统的业务主线：

```
教师上传课程文档 → 系统解析并切分知识块 → 向量化存入向量库
        ↓
学生基于知识库提问 → 问题向量化 → 检索相关知识块
        ↓
知识块 + 问题组装提示词 → 调用大模型 → 返回回答并展示引用来源
        ↓
教师查看学生问答记录与学习情况
```

三种角色：学生、教师、管理员。

## 三、版本风险提示（重要）

当前 `pom.xml` 使用了 **Spring Boot 4.1.1**，这是一个非常新的大版本，实际影响有三点：

1. Web  starter 由 `spring-boot-starter-web` 更名为 `spring-boot-starter-webmvc`，测试包同理；
2. MyBatis-Plus 需要使用 Boot 4 专用 starter，且 `IService` / `ServiceImpl` 的包路径已从 `com.baomidou.mybatisplus.extension.service` 改为 `com.baomidou.mybatisplus.spring.service`（开发中已踩过此坑）；
3. 网络上 90% 的 Spring Boot 教程、博客、问答均基于 3.x，遇到问题时可参考资料明显更少。

**建议**：若学校环境或答辩老师更熟悉 3.x，可考虑降回 Spring Boot 3.3.x/3.5.x（LTS 生态成熟，MyBatis-Plus 用 `mybatis-plus-spring-boot3-starter`，包名回归常规写法）。若坚持 Boot 4，则开发中遇到任何"包名找不到"的问题，第一反应应是版本差异，而不是代码错误。

## 六、下一步开发路线

按顺序推进，每步一个提交。

1. **接入统一返回体**：所有接口返回 `ApiResponse<T>`，前后端约定固定格式。
2. **JWT 登录**：签发令牌、刷新、退出；配合 Spring Security 做角色鉴权（STUDENT / TEACHER / ADMIN）。
3. **提交当前分支并发起 PR**：把 `feature/project-init` 合并进 `main`，保持提交历史干净。
4. **学科与教师-学科关联**：`subject`、`teacher_subject` 表 + CRUD。
5. **前端脚手架**：`campus-web`（Vue 3 + Vite + Element Plus），先做登录页与用户管理页，打通 Axios 跨域联调。
6. **知识库模块**：文档上传 → 解析（PDF/DOCX/TXT）→ 切分 → 存入 `knowledge_document` / `knowledge_chunk`。
7. **引入 Qdrant + Spring AI**：向量化与检索，实现 AI 问答并展示引用来源。
8. **统计与收尾**：ECharts 学习情况图表、接口文档、部署配置、论文材料。

第一版范围应严格控制在：三端登录 + 角色权限 + 用户与学科管理 + 文档上传解析 + AI 问答 + 引用来源 + 问答记录查看。

明确不做：模型微调、知识图谱、微服务、Redis、RabbitMQ、复杂审核流程、自动生成学习计划、智能组卷。

## 七、开发约定

- 数据库密码等敏感信息通过环境变量注入（`spring.datasource.password=${DB_PASSWORD}`），IDEA 运行配置中设置，不提交明文。
- 路径不写死，使用配置项（如 `app.upload-dir`），保证 Mac 与 Windows 均可运行。
- 文件编码统一 UTF-8，数据库 URL 指定 `serverTimezone=Asia/Shanghai`。
- 提交信息使用 `feat:` / `fix:` / `chore:` 前缀。
- `.idea/`、`target/`、`node_modules/`、上传目录与向量数据目录均加入 `.gitignore`。
- 本地 Docker 环境 DBeaver 连接需设置 `allowPublicKeyRetrieval=true`；`useSSL=false` 仅限本地开发。
